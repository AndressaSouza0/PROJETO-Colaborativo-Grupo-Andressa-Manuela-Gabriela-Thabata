O que é o Railway

Entenda por que usamos essa plataforma

O Railway é uma plataforma de hospedagem em nuvem que mantém servidores Node.js rodando 24 horas por dia, 7 dias por semana — mesmo com seu computador desligado.

✅
Por que Railway para este projeto? O servidor WhatsApp precisa ficar ativo o tempo todo para que os crons automáticos de notificação (8h e 14h) funcionem. No Railway, isso acontece na nuvem, sem depender do seu PC.
Situação Servidor local (seu PC) Railway (nuvem)
PC desligado ❌ Servidor para ✅ Continua rodando
Crons de 8h e 14h Só se o PC estiver ligado ✅ Sempre executam
Acesso ao sistema Só na rede local ✅ URL pública, de qualquer lugar
Custo Grátis ~US$ 5/mês (Hobby Plan)

3

Subir o código para o GitHub

O Railway busca o código diretamente do seu repositório

Se o repositório já existe no GitHub, basta enviar as mudanças recentes. Se ainda não existe, crie um novo.

Se o repositório já existe no GitHub:
Terminal (Git Bash / PowerShell) 
# Adiciona todos os arquivos modificados
git add .

# Cria um commit com as mudanças
git commit -m "feat: configuração para deploy no Railway"

# Envia para o GitHub
git push origin main
Se ainda não tem repositório no GitHub:
  • 1
    Acesse github.com e clique em "New repository"

    Dê um nome ao repositório (ex: sistema-biblioteca) e deixe como Privado.

  • 2
    Copie o link HTTPS do repositório criado

    Ficará no formato: https://github.com/seu-usuario/sistema-biblioteca.git

  • 3
    Conecte e envie o código pelo terminal
    Terminal 
    git remote add origin https://github.com/seu-usuario/sistema-biblioteca.git
git branch -M main
git add .
git commit -m "versão inicial"
git push -u origin main
⚠️
Arquivos sensíveis O .gitignore já está configurado para excluir a sessão do WhatsApp (.wwebjs_auth/) e o histórico de mensagens. Esses arquivos não devem ir para o GitHub.
4

Criar o projeto no Railway

Conectar o repositório e fazer o primeiro deploy

  • 1
    Acesse railway.app e faça login com sua conta GitHub

    Na tela inicial, clique em "New Project".

  • 2
    Escolha "Deploy from GitHub repo"

    Autorize o Railway a acessar seus repositórios, se solicitado.

  • 3
    Selecione o repositório do sistema de biblioteca

    Clique no repositório que contém o projeto e clique em "Deploy Now".

  • 4
    Aguarde o build — Railway detecta o Dockerfile automaticamente

    O Railway vê o arquivo Dockerfile na raiz do projeto e o usa para construir a imagem. O processo leva entre 3 e 8 minutos na primeira vez (instala o Chromium).

  • 5
    Verifique os logs de build em tempo real

    Clique no serviço criado → aba "Build Logs". Deve terminar com:

    Railway Build Logs 
    🚀 Servidor rodando em http://localhost:PORT
📱 QR Code gerado — escaneie pelo WhatsApp.
  • 6
    Gere uma URL pública para o serviço

    No painel do serviço → "Settings" → seção "Networking" → clique em "Generate Domain". O Railway criará uma URL como:

    https://sistema-biblioteca-producao.railway.app
🚂
Deploy automático a cada push A partir de agora, toda vez que você fizer git push para o GitHub, o Railway vai detectar e fazer o deploy automaticamente em poucos minutos.
5

Volume para persistência da sessão WhatsApp

Passo crítico — sem isso, você precisará escanear o QR a cada reinício

🔴
Por que isso é importante? O Railway usa containers efêmeros: quando o serviço reinicia (deploy, falha, etc.), o sistema de arquivos é resetado. Sem um volume persistente, a sessão do WhatsApp some e você precisa escanear o QR Code de novo.
  • 1
    No painel do seu serviço, acesse a aba "Volumes"

    Está no menu superior da tela do serviço.

  • 2
    Clique em "Create Volume"

    O Railway vai criar um disco virtual persistente.

  • 3
    Configure o ponto de montagem do volume

    No campo "Mount Path", coloque exatamente:

    Mount Path 
    /app/servidor-whatsapp/.wwebjs_auth

    Esse é o caminho onde o whatsapp-web.js salva a sessão dentro do container.

  • 4
    Clique em "Add Volume" para salvar

    O serviço vai reiniciar automaticamente. Aguarde o redeploy terminar.

✅
Após configurar o volume, você escaneará o QR Code apenas uma vez. A sessão ficará salva no volume mesmo se o serviço reiniciar.
6

Primeiro acesso — Escanear o QR Code

Conectar o WhatsApp ao servidor em nuvem

Com o servidor rodando no Railway, você precisa escanear o QR Code pelo WhatsApp uma única vez para conectar a conta.

  • 1
    Acesse a URL pública do seu projeto Railway

    Use a URL gerada no Passo 4.6. Exemplo:

    https://seu-projeto.railway.app/Fronted%20sistema/chatbot/chatbot.html
  • 2
    Na tela do chatbot, o QR Code aparecerá automaticamente

    O sistema detecta que o WhatsApp não está conectado e exibe o QR. Se demorar, aguarde alguns segundos e recarregue a página.

  • 3
    Abra o WhatsApp no celular → Menu → "Dispositivos conectados"

    No iPhone: Configurações → "Dispositivos vinculados". Toque em "Conectar um dispositivo" e escaneie o QR.

  • 4
    Aguarde a confirmação

    Após escanear, a página atualiza automaticamente e exibe "● WhatsApp Conectado" em verde. O servidor está pronto.

⏱️
O QR Code expira em 60 segundos Se expirar antes de você escanear, aguarde — a página gera um novo automaticamente a cada 45 segundos.
💡
Alternativa: endpoint direto do QR Code Você também pode acessar o QR Code diretamente pela API em:
https://seu-projeto.railway.app/api/qrcode
O retorno é um JSON com o QR em base64.

Acessar o sistema online

URLs que ficam disponíveis na nuvem

Com o servidor no Railway, o sistema inteiro é acessível de qualquer dispositivo com internet, usando a URL pública gerada:

Tela Caminho Função
Login /Fronted%20sistema/login/login.html Acesso de administrador
Chatbot /Fronted%20sistema/chatbot/chatbot.html WhatsApp + QR Code
Status API /api/status JSON com estado da conexão
QR Code API /api/qrcode QR Code em base64
Histórico API /api/historico JSON com envios recentes
Teste manual /api/notificacoes/executar (POST) Dispara os crons manualmente
🔒
Segurança O sistema usa login com bcrypt e sessionStorage para proteger as telas. No entanto, os endpoints de API não têm autenticação — considere não divulgar a URL pública do Railway para pessoas externas.
8

Como atualizar o servidor

A cada mudança no código, o Railway faz o deploy automaticamente

O Railway monitora o repositório GitHub. A cada git push, ele refaz o build e atualiza o servidor automaticamente — sem precisar acessar o painel do Railway.

Fluxo de atualização 
# 1. Faça as mudanças no código localmente

# 2. Adicione e commit as mudanças
git add .
git commit -m "fix: descrição da mudança"

# 3. Envie para o GitHub
git push origin main

# Railway detecta o push automaticamente e inicia o deploy (2-5 min)
⚠️
Durante o deploy, o servidor fica offline por ~1 minuto O Railway derruba o container antigo e sobe o novo. As notificações automáticas e o WhatsApp ficam indisponíveis nesse intervalo. O volume garante que a sessão seja mantida após o reinício.

Monitorar e ver logs

Como acompanhar o que está acontecendo no servidor

  • 1
    Acesse railway.app → seu projeto → seu serviço

    Você vê o painel principal com o status atual (ativo ou com falha).

  • 2
    Aba "Logs" — logs em tempo real do servidor

    É aqui que aparecem as mensagens do console.log do bot.js, incluindo confirmações de envio de WhatsApp e erros do cron.

    Exemplo de logs saudáveis 
    ✅ WhatsApp conectado!
📅 Cron de notificações automáticas ativado (8h e 14h).
⏰ [28/06/2026 08:00:00] Cron de notificações disparado.
  ✅ lembrete_3d → Maria Silva (5511999999999)
📊 1 notificação(ões) enviada(s).
  • 3
    Aba "Metrics" — uso de CPU e memória

    O servidor com Chromium usa em torno de 200–400 MB de RAM. Se o Railway mostrar uso muito alto e reinícios frequentes, considere fazer upgrade do plano.

📊
Histórico de mensagens enviadas Acesse https://seu-projeto.railway.app/api/historico para ver um JSON com todos os envios recentes. Essa informação também fica visível na aba "Histórico" do chatbot.
10

Problemas comuns

Soluções para as situações mais frequentes

🔴
Build falhou — "chromium: not found" ou erro do Puppeteer Verifique se o Dockerfile está na raiz do repositório (não dentro de servidor-whatsapp/). O Railway deve usar esse arquivo automaticamente.
🔴
QR Code some e precisa ser escaneado toda vez que o servidor reinicia O volume persistente não foi configurado (Passo 5). Configure o volume apontando para /app/servidor-whatsapp/.wwebjs_auth.
🟡
Status exibe "Servidor offline" no chatbot O Railway pode estar reiniciando o container. Aguarde 1–2 minutos e recarregue a página. Se continuar, verifique os logs em busca de erros.
🟡
Serviço "sleeping" — Railway pausando o servidor Isso acontece no plano gratuito quando não há requisições por um tempo. Atualize para o Hobby Plan (US$ 5/mês) para manter o servidor sempre ativo.
💡
Erro "WhatsApp não está conectado" ao tentar enviar mensagem A sessão foi perdida. Acesse a tela do chatbot pela URL do Railway e escaneie o QR Code novamente. Com o volume configurado, isso não deve se repetir.
